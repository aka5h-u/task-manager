# Task Manager API

A RESTful API for managing tasks, built with Node.js and Express. Supports creating, reading, updating and deleting tasks, with input validation and a layered project structure.

Built as Assignment 1 for the Airtribe Backend Engineering Launchpad.

## Tech stack

- **Node.js** 18+
- **Express** 4
- **tap** + **supertest** for testing

## Getting started

```bash
git clone <repo-url>
cd task-manager
npm install
```

Run the server:

```bash
npm run dev      # starts with --watch, restarts on file changes
# or
node app.js
```

Server runs at `http://localhost:3005`.

Run the tests:

```bash
npm test
```

## API

Base URL: `http://localhost:3005/tasks`

| Method | Endpoint     | Description      | Success | Errors   |
| ------ | ------------ | ---------------- | ------- | -------- |
| GET    | `/tasks`     | Get all tasks    | 200     | –        |
| GET    | `/tasks/:id` | Get a task by id | 200     | 404      |
| POST   | `/tasks`     | Create a task    | 201     | 400      |
| PUT    | `/tasks/:id` | Update a task    | 200     | 400, 404 |
| DELETE | `/tasks/:id` | Delete a task    | 200     | 404      |

### Task object

```json
{
  "id": 1,
  "title": "Set up environment",
  "description": "Install Node.js, npm, and git",
  "completed": true
}
```

### Validation

`POST` and `PUT` require all three fields in the body:

| Field         | Type    |
| ------------- | ------- |
| `title`       | string  |
| `description` | string  |
| `completed`   | boolean |

Missing or wrongly typed fields return `400`:

```json
{ "message": "Invalid types/ Missing fields" }
```

The `id` is generated by the server. Any `id` sent in the body is ignored.

## Project structure

```
task-manager/
├── app.js                          # Express setup, mounts routes
├── routes/task.routes.js           # Maps URLs + methods to handlers
├── middlewares/validateTask.js     # Validates request body for POST/PUT
├── controllers/task.controller.js  # Reads request, picks status code, sends response
├── repositories/task.repository.js # Data access, the only layer that touches task data
├── task.json                       # Seed data
└── test/server.test.js
```

Request flow:

```
request → routes → validateTask (POST/PUT only) → controller → repository → task data
```

Each layer has one job:

- **Routes** only wire paths to functions; no logic.
- **Middleware** rejects bad input before it reaches the controller.
- **Controller** handles `req`/`res` and HTTP status codes; never touches data directly.
- **Repository** reads and writes tasks; knows nothing about HTTP.
